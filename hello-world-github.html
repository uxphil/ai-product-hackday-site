Hello-world warm-up · GitHub route

Make it, publish it, change it

About 30–40 minutes the first time (estimate). No installs and no payment. Tick each step as you go.

Please read this firstThis is a personal learning exercise. Use fictional or public sample content only. Do not enter, upload or share any LBG data in AI tools, GitHub repositories, prompts, screenshots or published websites. More on staying safe.
What “published” means here. Your page and its file will be public on GitHub. Anyone with the address can see them. That’s fine for a sample sentence and not for anything else.

Part 1 · Make the page on your computer

No accounts needed for this part.

  1. Ask your AI assistant for the page2 min

    Open your AI assistant and paste this prompt.

    Write one complete HTML file for a tiny web page. It needs a heading that says "Hello, world", one friendly sentence, and a button that changes the sentence when clicked. Put everything in that single file, with no external libraries. Use sample text only, with no personal or work information. Reply with the code only.

    Not working, or no AI handy? Use this ready-made page instead 
    <!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Hello, world</title>
</head>
<body style="font-family: sans-serif; max-width: 32rem; margin: 3rem auto; padding: 0 1rem;">
  <h1>Hello, world</h1>
  <p id="message">This is my first web page, made as a warm-up for the hackathon.</p>
  <button onclick="document.getElementById('message').textContent = 'It works! I just changed this text.'">Change the text</button>
</body>
</html>

    Check that you have only the code. If your assistant added explanation around it, copy just the part from <!DOCTYPE html> to </html>.

  2. Save it as index.html3 min

    On a Mac

    1. Open TextEdit (press ⌘ + Space, type TextEdit, press Return).
    2. In the menu bar choose Format → Make Plain Text. This is important.
    3. Paste the code, then choose File → Save.
    4. Name it exactly index.html and choose Desktop. If it asks about .txt, choose Use .html.

    On Windows

    1. Open Notepad (press the Windows key, type Notepad, press Enter).
    2. Paste the code, then choose File → Save as.
    3. Set “Save as type” to All files.
    4. Name it exactly index.html and save it to the Desktop.

  3. Open it in your browser2 min

    Double-click index.html on your Desktop. You should see “Hello, world”, a sentence and a button. Click the button: the sentence should change.

    It doesn’t look right
    • You see lots of code instead of a page: the file was saved as plain text with a different name or type. On a Mac check you chose Make Plain Text before saving. On Windows check that “Save as type” was All files.
    • The name ends in .txt: on Windows, open File Explorer, choose View → Show → File name extensions, then rename the file to index.html.
    • It opens in a text editor: right-click the file and choose Open with, then your web browser.

Part 2 · Publish it

  1. Create your GitHub account5–10 min

    Go to github.com/signup. GitHub Free needs no card. Use your own personal email. GitHub emails you a code to verify your email address, and you can’t create a repository until that’s done.

    Your username will be part of your web address and will be public, so choose one you’re happy to share. Skip any optional questions or paid-plan offers. Already have an account? Sign in and move on.

    GitHub asks for something unexpected

    GitHub recommends two-factor authentication. It isn’t needed to finish this warm-up, but doing it later is a good idea. If sign-up is blocked or asks for a card, pause and ask for help at the clinic.

  2. Create a repository2 min

    A repository is just a folder GitHub keeps for you. Go to github.com/new.

    1. Repository name: hello-hackday
    2. Choose Public. Publishing for free needs this.
    3. Leave everything else alone, then press Create repository.

  3. Upload your page2 min

    1. On the new, empty repository, click the link uploading an existing file. (Later, you’ll find it under Add file → Upload files.)
    2. Drag index.html from your Desktop into the box.
    3. Press Commit changes. “Commit” means “save this to GitHub”.

    Your page is now saved in GitHub.

  4. Turn on publishing3 min

    1. Open the repository’s Settings tab, then Pages in the left-hand list.
    2. Under Build and deployment, set Source to Deploy from a branch.
    3. Set the branch to main, leave the folder as / (root), and press Save.
    I can’t find Pages, or it’s greyed out

    Check the repository is Public (Settings → scroll to the bottom, “Danger Zone”, for visibility). GitHub Free only publishes public repositories.

  5. Wait, then open your address1–10 min

    Your address will look like https://YOUR-USERNAME.github.io/hello-hackday/ and appears at the top of the Pages settings once it’s ready. GitHub says this can take up to 10 minutes. Refresh the Pages settings now and then. While you wait, have a look at the project themes.

    When it opens, send the address to your phone and open it there. That proves someone else can open it too.

    I get “404 – there isn’t a GitHub Pages site here”
    • Wait a few more minutes and refresh.
    • Check the file is called exactly index.html and sits at the top level of the repository, not inside a folder.
    • Check that Pages is set to the main branch.

Part 3 · Change it and publish again

  1. Change one sentence3 min

    1. In your repository, click index.html, then the pencil icon (Edit this file).
    2. Change the sentence between the <p> tags to something else that’s sample text.
    3. Press Commit changes, then Commit changes again in the box.

  2. See the new version1–10 min

    Wait a minute or two, then reload your page address. If you still see the old sentence, do a hard refresh (Ctrl + Shift + R on Windows, ⌘ + Shift + R on a Mac). It can take up to 10 minutes.

Short on time? Make the change in step 9 while the first publish is still waiting. You’ll then see both results at once. It teaches the same thing, just less clearly.

You’re ready ✔

  • ✔ You made a page on your computer.
  • ✔ It’s published at an address someone else can open.
  • ✔ You changed it and published again.
  • ✔ It’s saved in your GitHub repository.

Keep your repository: you’ll make a new one on the day. You may be asked to send your address to Phil on Teams To be confirmed.
