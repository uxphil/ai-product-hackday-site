Stay safe

Please read this firstThis is a personal learning exercise. Use fictional or public sample content only. Do not enter, upload or share any LBG data in AI tools, GitHub repositories, prompts, screenshots or published websites.

Don’t use any of these

  • Customer information
  • Colleague information
  • Internal documents
  • Code, or screenshots of systems
  • Passwords, credentials, API keys or access tokens
  • Confidential business information

Stay with fictional or public sample content. The mortgage theme uses a clearly made-up bank, and no real banking connection or customer data is ever needed.

Five things worth knowing

  1. Published websites may be visible to anyone who has, or guesses, the address.
  2. Public GitHub repositories expose their files to everyone, including earlier versions.
  3. AI tools handle data according to their own terms, your account and your settings. This event doesn’t claim any tool is approved by LBG and can’t guarantee confidentiality.
  4. Never paste a password, API key or token into a prompt, a repository or the code of a web page.
  5. Use your own accounts and make sure you keep access to your work after the day.

If you’re not sure

Ask before you share. Message Phil Bonhard on LBG Microsoft Teams. If you realise you’ve shared something you shouldn’t have, stop and tell Phil straight away so he can help you with the next step.

Optional detail

Why use a personal account and email?

The warm-up and your project belong to you. A personal account keeps them yours after the event, and keeps work identities out of public places. Usernames and published addresses are visible to others.

What about screenshots?

Screenshots are easy to get wrong: they can capture names, tabs, notifications and other windows. Share only a screenshot of your own sample product, and crop out everything else.

Can I make my GitHub repository private?

Yes, GitHub allows private repositories on a free account. However, free publishing with GitHub Pages needs a public one. A page published from a private repository is still public. Other routes keep the repository private; the Lovable route does this by default.

What if I want to try something more ambitious?

That’s welcome on the day, as long as it stays free of real data. If you add a service that needs a key, keep the key out of the page code and the repository, and ask a helper how to store it properly.
