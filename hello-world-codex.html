Hello-world warm-up · Codex does it for you

Let Codex do the setup

You describe what you want. Codex makes the page, creates your GitHub repository, uploads the page and turns on publishing. About 25–45 minutes the first time (an estimate).

Please read this firstThis is a personal learning exercise. Use fictional or public sample content only. Do not enter, upload or share any LBG data in AI tools, GitHub repositories, prompts, screenshots or published websites. More on staying safe.

Free or paid ChatGPT plan. Codex is listed on every plan, with usage limits, so a paid plan gives you more room. You still do four things yourself: create a GitHub account, install the app and sign in, approve its requests, and check the result. There is nothing to save, drag or configure by hand.

This is also a rehearsal for the day: you’ll build your real product with the same tool. Prefer to do it yourself for free? Use the manual route.

  1. Create your GitHub account5–10 min

    This is the one thing the tool can’t do for you. Go to github.com/signup. GitHub Free needs no card. Use your own personal email and verify it. Your username becomes part of your web address and is public. Skip optional questions and paid-plan offers. Already have an account? Move on.

  2. Install the ChatGPT desktop app and sign in5–10 min

    Download the ChatGPT desktop app from chatgpt.com/download, install it and sign in with your ChatGPT account. OpenAI’s plans page lists Codex on every plan including Free, with usage limits that vary, so a paid plan gives you more room.

    In the app, choose Codex from the dropdown.

  3. Give it an empty folder to work in2 min

    1. Create a new, empty folder on your Desktop called hello-hackday (right-click the Desktop, then New Folder on Mac or New → Folder on Windows).
    2. In Codex, open that folder as your project.

  4. Paste the first prompt and let it work8–15 min

    Paste this into the chat and press Enter.

    I am doing a small "hello world" warm-up for a hackathon, using only fictional sample content. Please work in this empty folder and do the following, one step at a time, explaining each step in plain language. 1. Create index.html: a tiny web page with a heading that says "Hello, world", one friendly sentence, and a button that changes the sentence when clicked. One file, no libraries, no personal or work information. 2. Check that Git and the GitHub CLI (gh) are installed. If either is missing, tell me what you need to install and ask before you do it. 3. Help me sign in to GitHub with gh using the browser method. Tell me the one-time code and where to type it. Never ask me for a password or token, and never store one. 4. Create a new PUBLIC repository called hello-hackday in my own GitHub account from this folder, commit index.html and push it. 5. Turn on GitHub Pages for that repository, publishing from the main branch and the root folder. 6. Tell me my web address (it looks like https://USERNAME.github.io/hello-hackday/), check whether it is live yet, and tell me clearly if I need to wait.

    The tool now creates the page, sets up GitHub, creates the repository, uploads the page and turns on publishing. You don’t save, drag or click anything in GitHub.

    Codex asks your permission before it uses the network, and the push to GitHub needs the network. Read each request and approve the ones about creating the page, git, the GitHub CLI and your hello-hackday repository. If it asks for anything else, say no and ask a helper.

    When it gives you a one-time code, a browser page opens (or go to github.com/login/device). Sign in to GitHub, type the code and approve.

    Something went wrong, or it asks for something odd
    • It asks for a password or token: stop. Say “Don’t ask for a password or token. Use the browser sign-in code instead.”
    • A Mac pop-up asks to install developer tools: choose Install and wait for it. It can take a few minutes.
    • On Windows it says it can’t install Git or the GitHub CLI: ask it to explain the manual download, or ask a helper.
    • It stops or runs out of usage: use the do-it-yourself route from step 5 instead. Your page may already exist in the folder.

  5. Open your address on your phone1–10 min

    The tool gives you a web address like https://YOUR-USERNAME.github.io/hello-hackday/. GitHub says it can take up to 10 minutes to go live the first time, so be patient. Open it on your phone: that proves someone else can open it too.

    I get “404 – there isn’t a GitHub Pages site here”

    Wait a few more minutes and refresh. If it’s still missing after 15 minutes, paste this into the chat: “My page shows a 404. Please check that GitHub Pages is on for hello-hackday and tell me what you find.”

  6. Change it and publish again3–10 min

    Paste the second prompt.

    Change the sentence on my page to something different (still just sample text), save it, and publish the change to GitHub. Then tell me when it should be live and how to check it.

    Wait a few minutes, then reload your address (hard refresh: Ctrl + Shift + R on Windows, ⌘ + Shift + R on a Mac). You should see the new sentence.

You’re ready

  • Codex made your page and your GitHub repository.
  • It’s published at an address someone else can open.
  • You changed it and published again.
  • It’s saved in your GitHub account.

Keep the repository. You’ll make a new one on the day. You may be asked to send your address to Phil on Teams To be confirmed.
