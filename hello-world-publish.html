Hello-world warm-up · Optional

Make it yours, then publish

Entirely optional. You’re already ready for the day once you’ve seen your page on your computer. These steps are for anyone who wants to play a bit more.

Please read this firstThis is a personal learning exercise. Use fictional or public sample content only. Do not enter, upload or share any LBG data in AI tools, GitHub repositories, prompts, screenshots or published websites. More on staying safe.

Why it’s optional. On the day, the first exercise for everyone is to put the page on GitHub and publish it, with helpers on hand. Doing it early just means less to do on the day. Use the same tool and the same hello-hackday folder as before. Haven’t done that yet? Start with the warm-up.

Part 1 · Change how it looks

  1. Add a smiley3–5 min

    In the same chat, paste this.

    Please add a smiley to my page and make it look a bit friendlier.

    Reload the page in your browser to see the change. Then try a few more requests of your own: a colour, a different message, a bigger heading. Ask for one change at a time.

Part 2 · Super optional: publish it

What “published” means here. Your page and its file become public on GitHub. Anyone with the address can see them. That’s fine for a sample sentence and not for anything else. This part needs your GitHub account and can take 15–30 minutes, much of it waiting. If anything gets fiddly, stop and leave it for the day.

  1. Ask your tool to publish it10–20 min

    Paste this into the same chat.

    I’d like to publish this page on the web with GitHub Pages. It only contains fictional sample content. Please go one step at a time and explain each step in plain language. 1. Check that Git and the GitHub CLI (gh) are installed. If either is missing, tell me what you need to install and ask before you do it. 2. Help me sign in to GitHub with gh using the browser method. Tell me the one-time code and where to type it. Never ask me for a password or token, and never store one. 3. Create a new PUBLIC repository called hello-hackday in my own GitHub account from this folder, commit the page and push it. 4. Turn on GitHub Pages for that repository, publishing from the main branch and the root folder. 5. Tell me my web address (it looks like https://USERNAME.github.io/hello-hackday/), check whether it is live yet, and tell me clearly if I need to wait.

    Your tool will ask your permission before it does things. Read each request. It’s fine to approve using git and gh for your hello-hackday folder and repository. If it asks for anything else, say no and ask a helper.

    When it gives you a one-time code, a browser page opens (or go to github.com/login/device). Sign in to GitHub, type the code and approve.

    Something went wrong, or it asks for something odd
    • It asks for a password or token: stop. Say “Don’t ask for a password or token. Use the browser sign-in code instead.”
    • A Mac pop-up asks to install developer tools: choose Install and wait for it. It can take a few minutes.
    • On Windows it says it can’t install Git or the GitHub CLI: ask it to explain the manual download, or ask a helper.
    • It stops or runs out of usage: leave it for the day, or try the do-it-yourself route, which needs no AI tool.

  2. Open your address on your phone1–10 min

    The tool gives you a web address like https://YOUR-USERNAME.github.io/hello-hackday/. GitHub says it can take up to 10 minutes to go live the first time, so be patient. Open it on your phone: that proves someone else can open it too.

    I get “404 – there isn’t a GitHub Pages site here”

    Wait a few more minutes and refresh. If it’s still missing after 15 minutes, paste this into the chat: “My page shows a 404. Please check that GitHub Pages is on for hello-hackday and tell me what you find.”

Prefer to do the publishing by hand, with no AI tool? Use the do-it-yourself route. Keep the repository: you’ll make a new one for your real project on the day.
